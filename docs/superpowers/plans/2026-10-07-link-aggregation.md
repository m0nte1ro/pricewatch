# Link Aggregation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make pasted store links the core of pricewatch: any public store page is read generically (with a user-confirmed fallback), checked on a configurable per-listing cadence, charted on every check, and alerted on without false deals.

**Architecture:** A `GenericAdapter` joins the dedicated adapters behind the existing `Registry`, keyed by hostname, and reads pages through four tiers (rule → structured → meta → heuristic), reporting the method on each `Snapshot`. A `store_rules` table holds user-confirmed selectors per host; one shared "confirm price" panel teaches them from the discovery preview and from the product page. Monitoring gains per-listing intervals and writes history on every check; alerts and best-price ignore unconfirmed heuristic readings.

**Tech Stack:** Existing only — Python 3.12, FastAPI, SQLAlchemy 2, Alembic, Jinja2, HTMX, BeautifulSoup, httpx, pytest + pytest-asyncio (auto mode) with `httpx.MockTransport`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-07-link-aggregation.md`

## Global Constraints

- No new runtime dependencies. No network in tests: retailer responses come from `httpx.MockTransport` in `tests/conftest.py`.
- One Alembic migration for this work, with a working downgrade; `tests/test_storage.py::test_migration_upgrade_and_downgrade` round-trips it. `migrations/env.py` already uses `render_as_batch=True` for SQLite.
- `./data` is owned by the container user. Local commands use `PRICEWATCH_DATA_DIR=/tmp/pw-dev` and a scratch alembic config (see Task 1).
- Lint: `.venv/bin/ruff check app tests scripts migrations && .venv/bin/ruff format --check app tests scripts migrations` must pass (line length 100).
- Intervals: default 60, minimum 5, maximum 10080 minutes (existing `Preferences` bounds; reuse them).
- Monetary alerts (`price_dropped`, `target_hit`, `insane_deal`) require EUR, `availability == "in_stock"`, an allowed condition, and — new — `method != "heuristic"`.
- Never bypass anti-bot systems: the generic adapter goes through the existing `Fetcher` (per-host spacing, 429 backoff, 403 cooldown) unchanged.
- Per `.claude/CLAUDE.md`: commit at the end of every task; never run, start, stop or rebuild Docker — tell the user when a rebuild is needed. Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Copy that the spec fixes: badge text `price unconfirmed`, badge text `store rule`, form error `Add at least one link, or pick stores to search`, rejection `Only public https:// store links can be monitored`, preview warning on a conflicting manual link `saved as pasted`.

## Review Focus

1. **JS-only page with no price in the HTML.** Expected: the link is kept (price unknown, availability unknown, `price unconfirmed`), not dropped — Task 5, `test_generic_page_without_price_is_kept_and_flagged`.
2. **Several prices on one page** (struck-through old price, bundle or recommendation prices). Expected: the current price is chosen and the others are offered as alternatives to confirm — Task 4, `test_heuristic_prefers_current_price_over_old_and_recommendations`; Task 7 covers the case where the heuristic still picks wrong.
3. **A store redesign breaks a confirmed rule.** Expected: fallback to the next tiers, listing flagged, no monetary alert from the heuristic value, rule still listed to re-confirm — Task 6, `test_broken_rule_falls_back_and_flags`; Task 8, `test_heuristic_price_never_alerts_or_counts_as_best`.
4. **`www`/non-`www` and tracking-parameter variants of the same link.** Expected: one store key, one listing — Task 5, `test_generic_store_key_and_url_variants_dedupe`.
5. **One generic store blocked (403) while another is fine.** Expected: per-host cooldown; the other store is still checked — Task 5, `test_generic_cooldowns_are_per_host`.

- Produces in `app/retailers/generic.py`:
  - `public_host(hostname: str) -> bool` — False for IPv4/IPv6 literals, `localhost`, names without a dot, and names ending in `.local`, `.localhost`, `.internal`, `.lan`, `.home`, `.arpa`, `.test`, `.example`, `.invalid`.

  - `currency_of(text: str) -> str` — `€`/`EUR` → `EUR`, `£`/`GBP` → `GBP`, `$`/`USD` → `USD`, else `EUR`.
  - `css_path(element: Tag, soup: BeautifulSoup) -> str` — see algorithm below.
  - `price_candidates(soup: BeautifulSoup) -> list[PriceCandidate]` — see scoring below; at most 8, best first.
  - `heuristic_availability(soup: BeautifulSoup) -> str` — `in_stock` / `out_of_stock` / `unknown`.
  - `@dataclass class Reading: title: str; price: Decimal | None; currency: str; availability: str; method: str; alternatives: list[PriceCandidate]`
  - `read_meta(soup: BeautifulSoup) -> Reading | None` — `meta[property="product:price:amount"]` or `meta[property="og:price:amount"]` through `money()`; `None` when absent; currency from `product:price:currency`/`og:price:currency` else `EUR`; availability from `product:availability`/`og:availability` through `availability()`, falling back to `heuristic_availability`; `method="meta"`, `alternatives=[]`.
  - `read_heuristic(soup: BeautifulSoup) -> Reading` — `candidates = price_candidates(soup)`; price and currency from the first candidate (or `None`/`EUR`); availability from `heuristic_availability`; `method="heuristic"`; `alternatives=candidates`.
- Module constants: `PRICE_HINT = re.compile(r"price|pre[cç]o|valor|amount", re.I)`, `OLD_HINT = re.compile(r"old|before|antes|anterior|regular|was|compare|strike|pvpr|list-price|riscado", re.I)`, `CONTEXT_HINT = re.compile(r"product|produto|item|detail|buy|offer", re.I)`, `NOISE_HINT = re.compile(r"related|recommend|sugest|also|carousel|slider|upsell|cross|bundle|accessor", re.I)`, `STOCK_HINT = re.compile(r"stock|avail|dispon", re.I)`, `CART_HINT = re.compile(r"adicionar ao carrinho|add to cart|comprar|buy now|añadir al carrito", re.I)`.

**`css_path` algorithm:** build the element's own segment: `tag#id` when it has an id matching `[A-Za-z_-][A-Za-z0-9_-]*` (then stop climbing); else `tag.c1.c2` using classes matching that pattern and not containing a run of four or more digits; else `tag`. If `soup.select(segment)` returns more than one element, append `:nth-of-type(n)` (n = 1-based index among same-tag siblings). Then prepend ancestor segments (same rules, no nth-of-type) joined with ` > ` until `soup.select(path)` returns exactly the element or six levels are used; return the path either way.

**`price_candidates` scoring:** for every element whose `class`/`id` matches `PRICE_HINT` or that has `itemprop="price"`, take `text = element.get_text(" ", strip=True)`; skip if `len(text) > 40` or `money(text)` is `None`. Score: `+2` own class/id matches `PRICE_HINT`; `+1` `itemprop="price"`; `+1` any ancestor within four levels matches `CONTEXT_HINT`; `-3` the element or an ancestor within three levels is `del`/`s`/`strike` or matches `OLD_HINT`; `-2` an ancestor matches `NOISE_HINT`. Order by score descending, then document order; drop duplicate selectors; keep 8.

**`heuristic_availability`:** (1) first element whose class/id matches `STOCK_HINT` and whose text gives a non-`unknown` `availability()`; (2) else `in_stock` when a `button` or `input[type=submit]` without the `disabled` attribute has text/value matching `CART_HINT` (anchors do not count); (3) else `out_of_stock` when the page text contains `esgotado`, `indisponível`, `sem stock`, `fora de stock` or `out of stock`; (4) else `unknown`.
